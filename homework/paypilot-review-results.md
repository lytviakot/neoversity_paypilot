# PayPilot US-01 review: results

Status as of 2026-10-04. Every finding started as a hypothesis. **Confirmed** means the bot replies and tool traces we collected support it; **Not an issue** means they rejected it; **Not yet checked** means we don't have enough evidence either way.

The findings are split into three parts so each can be fixed separately:
- **Part A: System prompt** (PayPilot base.v1): defects in the prompt's wording. IDs **H01–H32**.
- **Part B: User story** (US-01): defects in the story's wording. IDs **S01–S15**.
- **Part C: Bot behaviour**: the tested bot doesn't follow the prompt, while the etalon does. IDs **C1–C9**.

**Questions and etalon comparison.** Every table shows the exact question sent, its run ID (R01–R56), and the etalon answer to the same question where available. Appendix D lists everything side by side. **No shorthand is used:** every question appears exactly as it must be sent.

## How to read the etalon comparison

The etalon shows the **reference behaviour** of the test stand. It is not automatically the *correct* answer; correctness is checked against the tool data (the trace). *Assumption: the etalon runs the same system prompt and tools as the tested bot. If it doesn't, the "regression" outcomes below need re-checking.*

| Outcome | Meaning | What happens to the finding |
|---|---|---|
| **Both wrong → spec defect** | The etalon gives the same kind of wrong answer as the tested bot, compared with the tool data. | **Stays in Part A / B.** The defect is in what both versions share (prompt, story, tariff, tools). |
| **Same, acceptable → expected stand behaviour** | Both behave the same and nothing contradicts the tool data or policy. | **Not an issue** on this stand. |
| **Tested bot worse → regression** | The etalon gets it right with the same prompt; the tested bot doesn't. | **Moves to Part C** (bot behaviour). The prompt line can be read correctly, so it isn't the main cause. |
